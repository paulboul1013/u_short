## Overview

Add one dependency-free browser page at `GET /` as a small vertical increment
over the completed URL Shortener v1. The source asset is embedded at build time,
Router owns delivery and root-route semantics, and the existing Server, HTTP,
Shortener, persistence, and redirect contracts remain intact. This increment
explicitly replaces one v1 behavior: `GET /` changes from an empty-Short-Code
HTTP 400 response to the HTTP 200 HTML page; all other v1 contracts remain
unchanged.

## Architecture decisions

- `GET /` is an exact Router-owned route before `/{code}`; query strings are
  excluded from matching, and unsupported methods return 405 with `Allow: GET`.
- `web/index.html` is the only UI source asset. CMake embeds it in the binary, so
  the executable has no runtime file-path dependency.
- The HTML response is at most `HTTP_MAX_BODY_BYTES` (4096 bytes), enforced
  during the build.
- `http_response_t`, `router_handle`, `server_run`, and all other public C
  interfaces remain unchanged.
- The page uses a same-origin `POST /shorten`; backend validation remains
  authoritative.

## Risks and mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| UI exceeds the fixed response bound | Build or response failure | Enforce 4096 bytes at build time and keep one compact dependency-free asset |
| Generated bytes differ from source | Incorrect or unsafe page | Generate deterministically from the source and assert representative content in Router and acceptance tests |
| Root is captured by `/{code}` | Wrong 400 or redirect behavior | Match exact `/` first and test `/`, `/?x`, and normal Short Codes |
| Runtime depends on repository layout | Installed binary cannot serve UI | Run acceptance from a directory without `web/index.html` |
| Browser checks diverge from backend | Inconsistent validation | Keep browser checks advisory and surface backend 400 responses |
| UI breaks v1 routes | Regression | Run the complete existing test and acceptance suite before completion |
