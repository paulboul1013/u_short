# URL Shortener v1

## Status

**Completed and verified on 2026-09-12.**

The implementation satisfies `docs/ACCEPTANCE.md`; its completed execution
record is `docs/exec-plans/completed/url-shortener-v1.md`. Automated build and
test verification passed, and the redirect flow was also verified manually.

## Goal

Implement a minimal, single-process URL shortening service in C17 for learning system design and implementation boundaries.

The service runs locally in a trusted environment. Authentication, authorization,
rate limiting, TLS termination, and distributed deployment are outside v1.

Persisted Short URLs must remain valid after the process restarts.

## Core functionality

### POST /shorten

Input:

```json
{
    "url": "https://example.com/article"
}
```

Output:

```json
{
    "code": "21",
    "short_url": "http://localhost:8080/21"
}
```

The code shown above is illustrative. The actual Short Code is the Base62 encoding
of the newly inserted database record ID. Every request creates a new record and
a new Short Code, including repeated submissions of the same Original URL.

The request must be a valid JSON object containing exactly one `url` member. The
member must be a string. Normal JSON whitespace, string escapes, and additional
unknown members are accepted. A missing, duplicated, or non-string `url`, or
malformed JSON, returns HTTP 400.

The Original URL must:

- be no longer than 2048 bytes
- be an absolute `http://` or `https://` URL with a non-empty host
- contain no whitespace or ASCII control characters
- use an ASCII URI reg-name or bracketed IPv6 address as its host; user-info is
  not accepted and an optional port must contain only decimal digits

The service does not contact the destination to validate its existence or
reachability. Apart from JSON string decoding, it stores the Original URL without
normalization and returns the same value in the redirect `Location` header.

Success returns HTTP 201 with `Content-Type: application/json`.

### GET /{code}

Decode the code and redirect to the original URL.

Response:

HTTP 302
Location: https://example.com/article

A Short Code is invalid and returns HTTP 400 when it is empty, contains a
character outside the Base62 alphabet, overflows `uint64_t`, or uses a
non-canonical leading zero. A canonical decoded ID with no database record returns
HTTP 404. `0` is canonical but is not generated by SQLite, so it normally returns
HTTP 404.

Base62 supports the complete `uint64_t` range for codec testing. Persisted SQLite
IDs are limited to the database's signed 64-bit integer range.

### GET /health

Return:

HTTP 200
OK

The response uses `Content-Type: text/plain`.

## HTTP behavior

- A request to a known path with an unsupported method returns HTTP 405 and an
  appropriate `Allow` header.
- An unknown path returns HTTP 404.
- Error responses require the correct status code and a short plain-text body;
  v1 does not define a JSON error schema.
- The server accepts HTTP/1.0 and HTTP/1.1 requests using CRLF line endings.
- Header names are case-insensitive.
- `POST /shorten` requires one valid `Content-Length`. A missing, duplicate,
  conflicting, or malformed length makes the request invalid.
- Transfer encodings, including chunked request bodies, are unsupported and
  return HTTP 501.
- Other malformed requests return HTTP 400.
- The server handles one request per TCP connection and then closes it.
- Each request has a two-second total processing deadline measured with a
  monotonic clock, so slow incremental input cannot occupy the server forever.
- Request headers are limited to 8 KiB and request bodies to 4 KiB.

## Runtime and storage

- The single-threaded blocking server listens on `127.0.0.1:8080`.
- Short URLs use the fixed base URL `http://localhost:8080`.
- SQLite data is stored in `url_shortener.db` in the current working directory.
- The database schema is created automatically on startup.
- Each URL Record stores `created_at` as Unix time in UTC seconds. It is not
  exposed through the v1 HTTP API.
- Failure to open or initialize the database is written to standard error and
  terminates the process with a non-zero status.
- An internal or database failure while serving a request returns HTTP 500.
- On `SIGINT` or `SIGTERM`, the server stops accepting connections, closes the
  listening socket and database, and exits normally.

## Build dependency

SQLite is a required system development dependency discovered with CMake's
`find_package(SQLite3 REQUIRED)`. The SQLite amalgamation is not stored in this
repository.

## Scope exclusions

Version 1 does not provide:

- listing Short URLs
- deleting or editing Short URLs
- user-selected Short Codes
- expiration
- visit statistics
- user accounts
